# Backend build prompt — Cyber One

Implement the exact contract in 03-API-CONTRACT.md for a Node.js 22+ backend deployable as a Vercel function. Support the frontend without contradictory status fields or fake VPN success. Use PostgreSQL for shared deployed persistence and a local encrypted file for a dependency-free demonstration. Refuse ephemeral file storage on Vercel.

Security and identity:
- Validate all input server-side. Normalize unique usernames; enforce matching 12–128 character passwords. Hash salted passwords with scrypt; never encrypt passwords reversibly or log credentials.
- Generate ten 12-character alphanumeric codes using a cryptographically secure source. Preserve case and collision-check keyed code hashes across all current accounts under serialized database writes. Display codes once, store keyed hashes only. Honor requested unlimited reuse, but document replay risk and lack of phishing resistance. Do not call these one-time codes or high-assurance MFA.
- For the hackathon, use explicitly labeled sample identity approval with a required PNG/JPG sample-image upload up to 2 MB, basic file-format validation and immediate discard; never store images. With DEMO_MODE disabled, fail registration closed until an actual identity-provider integration exists. Production architecture should retain only a provider status and deduplication token, not raw ID images; include retention/consent/provider review before enabling.
- Use cryptographically random sessions, hash stored session tokens, HttpOnly/SameSite cookies, Secure on Vercel, one-hour expiry, sign-out revocation, origin checks and JSON content types. Enforce password → code → disclosure → ready stages on the server. Store versioned signed acknowledgements each session. For a newly created account, enforce a ten-second backup-code hold before allowing disclosure completion. Rate-limit login, code, administrator login and registration.

Households and temporary profiles:
- At most eight linked mini-user logins with unique global usernames, salted password hashes and separate backup-code hashes; never more than one temporary profile per owner. Serialize concurrent writes across instances. All family activation controls point at that one profile. Derive mini-user ownership from the authenticated creator session, never a client parent ID. Mini sessions reference the household plus a member ID; validate both before authorizing. Return sanitized family status only, never hashes. Mini users cannot manage siblings or delete shared data. Aggregate the shared profile active state from the owner and every mini user, so disconnecting one person does not disconnect others. The owner sees individual On/Off state; region changes are blocked while an active profile uses another region. Removing a member revokes their sessions and purges household snapshots. Existing labels can receive login credentials without adding another member. Pausing and deleting are distinct.
- Simulation mode stores a documentation-only IP and requested region but must never assert that traffic is protected. With demo mode disabled, return unavailable until a native VPN client and gateway adapter are connected. Vercel is the control plane, not the tunnel gateway.
- Only owners may manage their household. Incidents are authenticated, operator-reported demonstrations, not automatic breach detection. Pause flagged profiles and prevent reactivation until deletion. Poll notifications; disclose no push/email integration.

Encryption and lifecycle:
- Encrypt persisted application state using AES-256-GCM with a fresh random 96-bit nonce per encryption. Keep the 256-bit master key and code pepper outside the database and repository. Snapshots are independently encrypted, tagged and timestamped per household.
- Snapshot/re-encrypt every ten minutes through a running local scheduler or authenticated external deployment scheduler. Every run preserves plaintext semantics but changes ciphertext. This does not rotate the master key or make stolen ciphertext disappear. Document key management limits.
- Keep snapshots for 24 hours, enforcing expiry on backup runs. Same-database snapshots are not disaster-recovery backups; recommend a separate encrypted backup target for production.
- Account deletion requires the exact phrase plus a server-enforced two-second challenge. Remove account, sessions, all linked family credentials, temporary profile, consent records and associated application snapshots. Temporary-profile deletion also removes all household snapshots to prevent resurrection. Provider snapshots and forensic disk erasure cannot be guaranteed by this application.
- Admin console uses separate secret-authenticated sessions, limited plaintext metadata and ciphertext only. Allow manual snapshot creation and confirmed cutoff deletion. No customer access to other accounts or admin endpoints. SQL queries are parameterized; runtime role gets SELECT/INSERT/UPDATE only, migration role creates the table.

Protective impact and validation:
- Implement local URL screening of harmless .test phishing fixtures plus unsafe URL scheme/embedded credential checks, without fetching arbitrary input. Unmatched means unknown. Do not claim broad phishing protection.
- Test auth-stage bypass, account isolation, code generation/reuse, concurrent-safe household invariant, deletion delay and cascade, snapshot cutoff, incident pause, bad input, and encryption tamper detection.
- Document that a fully compromised application can access decrypted data and master keys, encryption-at-rest does not replace access control, and changing ciphertext cannot undo exfiltration.

Email recovery: implement Resend transport with server-only RESEND_API_KEY and EMAIL_FROM plus a trusted APP_URL. Require valid normalized emails on registration. Only verified addresses may recover accounts. Existing full-session accounts can add an email after password verification; verified address changes are disabled pending a secure change workflow. Store only token hashes, with 30-minute verification and 15-minute recovery expiry. Bind tokens to actor ID, household and email; enforce purpose and single use, and invalidate outstanding links after recovery. Return generic reset-request responses with timing mitigation and limits. Password-only recovery preserves codes; code-only recovery requires current password; combined recovery relies on the verified mailbox. Revoke only affected actor sessions, pause its profile, purge household snapshots and send a change notification. Deletion removes recovery records. No debug tokens or passwords/codes may be returned by request endpoints or email logs. Await email delivery requests after committing token state; report configuration limits and delivery failures honestly.
